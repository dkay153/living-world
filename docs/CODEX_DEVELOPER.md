## Owner setup and operation

Use `npm run admin:open`, then **Codex developer**. Browser or headless sign-in is completed by the owner with OpenAI. Choose an account model or automatic routing, explicitly choose no time limit (blank) or a 1–1,440 minute per-task watchdog, verify isolation and enable developer execution. Living World does not impose a local daily task or minute cap. Existing selections are preserved; no model is invented. Restart automatically verifies isolation before dispatching work. Failure blocks execution and backs off for two minutes. [Official authentication guidance](https://learn.chatgpt.com/docs/auth).

**Independent stewardship** controls self-selected work, the interval (1–1,440 minutes) and automatic visual publication. Its fresh-install defaults are paused, a 30-minute interval and publication off. Activating it does not change account limits or the separate saved API configuration. A cycle waits behind queued owner work and uses a unique request receipt. Account usage is shared with other clients; cached exhausted account windows block dispatch until their reset. [Official account methods](https://learn.chatgpt.com/docs/app-server).

Pause developer execution to abort the current attempt and block all new work. Pausing independent work stops automatic selection. Disconnect affects only this project's account. Rollback restores the prior valid visual pack and pauses automatic publication. Controls remain authenticated, same-origin, CSRF-protected and audited.

Cycles avoid overlapping work and enforce a cooldown. Three consecutive uncertain execution failures open a scheduling circuit. ## First protected deployment lane

`public/art.json` defines replaceable colors and optional original tile/sprite animations; see [DEVELOPER_LOOP.md](DEVELOPER_LOOP.md). The live renderer consumes the **host's validated artifact**, independently of proposed source edits. Pixel data cannot contain code or URLs. The host validates exact fields, known dimensions/entities, opacity, terrain distinction, label-outline contrast, rendered terrain distinction, palette contrast, silhouettes, timing, large flashing regions and size. Candidate tests are an additional gate, never a substitute for that validator. A constitutional/instruction change blocks this release lane.

Publication checks that the active baseline did not change during development, then commits the immutable artifact, job completion, outcome and audit together. Previous versions remain in `visual_releases`; an artifact/hash validation failure restores a prior valid pack or the original seed. The browser polls visual data once a minute. Saves, encounter commands, collision and owner privileges cannot be changed by this data lane. The developer cannot replace this host validator by editing its copy. Quality complaints can be addressed through owner rollback and later model tasks; automatic aesthetic regression detection is not implemented.

The automatic compartment is an initial capability, not the final creative/technical ceiling. Source proposals may change mechanics, engine, transport, persistence, rendering and architecture within the constitution. A separate protected production runtime, independent saved-world compatibility tests, service-isolated staging, migration backups and deployment recovery drills must precede general automatic code promotion. Executing candidate server code on the privileged owner host would defeat the access boundary, so source proposals remain retained until that compartment exists.

## Isolation and process ownership

The account lives in `DATA_DIR/codex-home`, separate from the desktop account. The host only exposes sanitized account email/plan, catalog and rate windows through private stdio RPC to `codex app-server`. No tokens or general RPC/shell endpoint reach the browser. Authentication links are HTTPS on `auth.openai.com`. The fixed profile forces ChatGPT/OpenAI authentication, excludes inherited API keys and arbitrary Node injection, requests Windows MXC and blocks command networking. There is no unrestricted fallback. [Permission profiles](https://learn.chatgpt.com/docs/permissions), [Windows isolation](https://learn.chatgpt.com/docs/windows/windows-sandbox).

Source snapshots include named source roots and manifests, with the installed `ws` dependency copied without installation. They exclude live databases, backups, credentials, environment files, Git metadata, outputs and unrelated directories. Symlinks are rejected. Every actual copy undergoes file/network canaries. The broker can reach OpenAI; generated commands cannot reach live localhost services. Built-in web search is disabled.

`codex exec` uses the exact owner model, ephemeral sessions, ignored external execution rules and structured events. A watchdog owns each process tree, stops it on cancellation/server IPC loss and bounds output to 2 MiB. With an explicit unlimited setting, planning, implementation and candidate checks have no elapsed-time cutoff. Finite attempts retain their configured model timeout and two-minute offline checks. Connection, isolation and preparation probes retain their diagnostic timeouts. Zero in the existing run-history minute column records an unlimited attempt; older positive values retain their meaning. Copies are limited to 2,000 files, 512 KiB/file and 25 MiB. This is native Windows process/filesystem/network isolation, not a Windows Sandbox VM or CPU/memory-limited container. Linux/server isolation requires its own acceptance drill. [Official non-interactive execution](https://learn.chatgpt.com/docs/non-interactive-mode).

The host test launcher enumerates only trusted top-level tests and never discovers saved candidate tests recursively. Preliminary candidate checks execute inside MXC, where outbound loopback remains blocked. The mandatory independent Docker source stage builds the sealed artifact and runs every top-level candidate test, including real HTTP/WebSocket/browser integration, without access to the live owner service.

Native instruction discovery is pinned to the candidate `AGENTS.md` root, so it does not traverse denied ancestor projects. Each attempt first renders its instruction/image input with the model-free CLI diagnostic. This catches preparation failures before inference. Errors retain only fixed diagnostic categories, not raw account-bearing CLI logs. The wake control queues a new, explicitly audited independent attempt; it never replays the old receipt.

## Local acceptance evidence — 2026-10-10

On this Windows host, v0.5.0 passed 42 application tests and 34 offline tests inside actual MXC. A schema-5 backup preceded migration; player, event, gameplay and item counts were preserved. Native instruction/image preflight exposed a denied ancestor-instruction read and passed after the root marker was pinned, without inference. The initial failed attempt was retained. A new self-directed `gpt-5.6-sol` attempt then completed, chose a test-runner portability improvement without a supplied feature task and passed all 33 host-dispatched isolated checks. Its source proposal was retained; this attempt did not publish art. Visual publication, stale-baseline rejection and rollback were exercised with fixtures rather than attributed to this real model task. The owner account/model/time controls were preserved and the separate API worker stayed disabled. This verifies a bounded independent development cycle, not the full unattended operator/production acceptance criteria.

Operator/tool self-upgrades now have a separate confined installation, fault rollback and restart path; see [HOST_OPERATOR.md](HOST_OPERATOR.md). The fixed authority kernel, saved owner account settings and history guard remain outside candidate replacement.

Authenticated owner tasks may supply resumeFrom with a terminal failed/cancelled/interrupted run ID. This starts a fresh account task; it never resumes or replays the prior model turn. Retained changes are data only: fresh planning must cover them, every source baseline hash must match, protected changes are refused, and implementation must explicitly accept the recovered source. Missing acceptance, stale files or failed full contained validation block publication. The previous run stays terminal and its diagnostics stay retained. Saved model/effort/limits and ordinary scheduling are unchanged. This interface currently requires an owner task; it does not grant candidates access to host control APIs.
