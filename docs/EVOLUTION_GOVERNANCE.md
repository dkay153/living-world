# Evidence-led evolution

Living World is intended to improve itself, not to create change for its own sake. A passing test means a candidate did not violate the checks it ran. It does not prove that players needed the change, that the new version is more enjoyable, or that a healthy experience should be disturbed.

## The evolution record

Every planning attempt must create an `evolution-review.json` alongside its change plan and state-impact declaration. The host accepts only a record that names:

- the observed problem and the evidence behind it;
- the current baseline, including signals that are unavailable rather than invented;
- a falsifiable hypothesis and one primary variable;
- the player cohort or representative journey affected;
- protected guardrails;
- a success signal, stop/rollback signals and an observation window; and
- the explicit case for doing nothing.

Independent work whose baseline is entirely unavailable becomes **observe**, not an automatic live intervention. It can retain a quiet observation, improve lab instrumentation, or create a candidate for later review. This is a successful protective decision when the present experience is healthy.

An owner-directed task may still produce a candidate, but it carries the same review record and cannot bypass protected identity, authority, staging or recovery checks.

## Preventing churn

The AI must not stack speculative edits. It works on one primary variable at a time, preserves the last known-good artifact, and waits for the declared observation before treating an outcome as a lesson. A new candidate must cite a new regression, a measured opportunity, a safety/repair need, or a durable owner direction. Cosmetic novelty is not sufficient evidence.

For player-facing work, the protected journeys include exploration, distinct command-driven encounters, behavior-led identity and recovered history. A regression in any required journey, authority check, accessibility check, operational signal or declared guardrail stops expansion and triggers rollback where the release lane is reversible.

## Current capability

The current local lane can publish only validated visual data. It requires a complete review and a trusted World Lab baseline; it does not claim player-outcome measurement. General source candidates are retained until a separate staging runtime, immutable artifact manifest, candidate World Lab evidence and recovery drill are available.

On this host, Windows Sandbox, Hyper-V, Docker and Podman were unavailable during the 2026-10-11 readiness check. The promotion broker is therefore deliberately blocked. It records the exact missing capability instead of executing candidate source on the owner host.
